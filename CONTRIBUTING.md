# Contributing to LawLearn Commons

Thank you for helping make legal learning more accessible.

## Before opening a pull request

1. Check existing issues and the roadmap so work does not conflict.
2. For a substantial change, open an issue first and describe the user need.
3. Keep changes small, accessible, mobile-friendly, and understandable to new contributors.
4. Never add API keys, private student notes, personal data, or copyrighted course material.
5. For legal content, identify the jurisdiction, source, source date, reuse permission, and reviewer. Do not present a contributor's summary as an authoritative source.

## Development

```bash
npm install
npm test
npm run dev
```

Before submitting, run `npm test` and manually check the main pages at desktop and mobile widths.

## Pull requests

- Explain the problem and solution.
- Include screenshots for visible UI changes where practical.
- List tests performed and any limitations.
- Note any new dependency and why it is needed.
- Do not include secrets or real personal information.

## Legal content contributions

A link to a public webpage is not the same as permission to republish its contents. Prefer linking to official material and recording source metadata. Check the source's terms before downloading, indexing, transforming, or redistributing material. Every legal resource should carry a jurisdiction and an “as at” date where applicable.

## Decisions

For now, maintainers review issues and pull requests publicly. Decisions should prioritise learner safety, accuracy, accessibility, privacy, and maintainability. The maintainers may request evidence, revisions, or a qualified legal-content review before accepting legal material.
